The Urban Challenge

Why static signals fail dynamic traffic.

Many junctions use fixed-timer signals or manual police control with no real-time view of vehicle density, which can lead to long waiting times, wasted fuel and delayed emergency response.

This prototype observes traffic patterns and shows, at a basic level, how live data could support better signal timing.

{{ icons.icon_clock(size=24) }}

Waiting time

{{ icons.icon_fuel(size=24) }}

Fuel use

Architecture & Specifications

Tech stack and hardware

Finalized technology decisions and local compute requirements for edge-friendly execution.

Software Stack

Core Engine
  • Python 3.10+ Backend runtime & pipeline
  • OpenCV Frame capture & pre-processing
  • YOLOv8n (Ultralytics) Object detection & classification
  • ByteTrack Multi-object tracking & counts
  • Flask Web application & SSE streaming
  • SQLite Local embedded time-series logs
  • Chart.js Client-side analytics charts
  • scikit-learn Trend computation & analytics

Hardware Requirements

Deployment Specs
  • Compute Device A laptop (no GPU needed)
  • Video Input A webcam or recorded traffic video
  • System Memory 4 GB RAM minimum
  • Disk Storage ~500 MB (PyTorch CPU + model weights)

Pretrained Model Note: A pretrained COCO model is used and no custom training is done. Vehicle classes (car, motorcycle, bus, truck) are recognized out of the box using general weights.
